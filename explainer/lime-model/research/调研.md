# 调研：消石灰制备参数控制模型

> 唯一事实来源：本项目文件（`模型/README.md`、`模型/config.py` 等）。每条数字带出处。
> 视频定位：3–5 分钟中文，40–50 句，一句一镜头。

## §1 执行摘要

- 模型一句话：给脱硫消石灰生产线配的**节拍式温度守护控制器**——用水率和生石灰流量两个旋钮，把出口温度 T3 守在 100–130℃（目标 118℃）。
- 核心结论：控制对象是**非最小相位**的（加水后温度先升后降），所以不能用常规 PID 连续调，必须「一次动作 + 等 35 分钟」；且积分项会累积不可控扰动，初版 PI 被反事实仿真推翻，现行版本是**宽守护带 + 最小干预，无积分**。
- 守护带现行值 = **工艺区间 100~130℃**（《控制逻辑.txt》硬约束）。曾收窄到 110~122 导致偏低班次翻车 −2.1pp，改回后偏低班次 100%、超限班次 56.7→58.3%（动作 8→4 次）：动作更少、效果更好。
- 职责边界（最新重构）：模型**只算水流量与生石灰流量给定值**，停机/切自动/料位/联锁全与模型无关，一切保护只写 notes 不改输出。
- 最适合视频讲的 3 个点：①加水温度反而先升（反直觉开场）；②初版控制器越勤快越差，反事实仿真把它否了（叙事高潮）；③现行控制律的极简之美——106–126℃ 之间什么都不做。

## §4 术语表

| 中文 | 英文 | 一句话 |
|---|---|---|
| 非最小相位 | non-minimum phase | 响应先朝反方向走再朝目标走（加水先升温） |
| 比例控制 / Kp | proportional control | 输出正比于偏差，无记忆 |
| 积分项 | integral term | 累积历史偏差，会把不可控扰动攒成漂移 |
| 稳态 / 启动阶段 | steady state / startup | 允许信号置 1 且 T3≥100℃ 即进入稳态闭环，否则只监护 |
| 事件研究 | event study | 找干净阶跃事件，对齐事件前基线看响应 |
| 响应核 | response kernel g[k] | 一次输入阶跃后输出随时间的响应序列 |
| 反事实仿真 | counterfactual simulation | 同一扰动序列下只替换操作序列，对比结局 |
| 共同随机数 | common random numbers | A/B 双方共用同一扰动 d[t]，差异才归因于操作 |
| 守护带 / 死区 | guard band | 带内不动作，避免小偏差大折腾 |
| 最小干预 | minimal intervention | 能不动就不动，动也用最小步长 |
| 安全联锁 | interlock | 最高优先级硬保护，任何阶段不可覆盖 |
| 阶跃 | step | 输入的一次突变，响应分析的原料 |
| 滞后 | lag | 作用到见效的延迟；T3 稳态滞后 30 min |

## §5 比喻建议

- **非最小相位**：大船左转时船身先向右倾——想让它往左，得先接受它暂时向右。或：调淋浴水温，往热调的那一刻反而先凉一下。
- **PID 在此翻车**：你往热调了水温，10 秒后水更凉了，你判断「调反了」猛往回调——其实只是热还没到。每一步都「正确」，合起来永远振荡。
- **积分漂移**：追一个永远追不上的目标，越落后越用力，最后冲出跑道。病例数字：水率从 630 一路压到物理下限 350。
- **守护带 / 最小干预**：好园丁不每天把花拔出来看根。106–126℃ 之间，控制器什么都不做。
- **节拍等待**：炖汤不能每分钟掀盖尝味——掀盖本身就在坏事。等 35 分钟是控制律的一部分。
- **电流三级保护**：37.5℃ 观察、38.5℃ 吃药、39.5℃ 送医。预警（禁增量）/ 降载 / 停产。
- **共同随机数**：让两个学生考同一份卷子、遇到同一道超纲题，分差才能全记在水平上。
- **响应核**：往水池丢一颗石子，把涟漪的形状记下来；以后任何投石组合都能按这份「涟漪档案」推算水面。
