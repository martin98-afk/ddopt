"""消石灰制备 · 预测 PI 控制模型

============================ 与 模型/ 目录的关系 ============================

本目录是 模型/ 的**并列分支**，不改 模型/ 任何一个文件。

  模型/            现役：斜率规则（趋势预判 PI），已在跑
  模型_预测PI/     备选：预测 PI / Smith 预估器，待标定后启用

两者共用 模型/ 的信号调理、控制器骨架、时序库客户端、微服务框架，
本目录只替换温度控制律，并在 标定参数.py 里集中放置待标定的对象参数。

============================ 为什么要换控制律 ============================

现役斜率规则的动作幅度是「每拍固定步长」(step_max=25 L/t)，与真实时间无关。
控制周期缩短 N 倍，单位时间动作幅度就放大 N 倍 —— 现场按 10 秒调用时会自激。
（实测：周期 10min→10s，水率行程从 14 L/t/h 涨到 104 L/t/h。）

预测 PI 的动作幅度由对象增益反解：偏差 1℃ 该动 1/|K| = 6.62 L/t，
与调用周期无关。这是它能安全跑高频调用的根本原因。

============================ 预测 PI 原理 ============================

对象拆成两部分：G(s) = G0(s)·e^(-θs)
    G0(s)   无死时间的一阶惯性  K/(τs+1)
    e^(-θs) 纯死时间 θ

每拍三步：
    y0(k)      = K·x(k)                    不带死时间的模型输出
    y0_del(k)  = y0 延迟 θ                 带死时间的模型输出
    d_hat(k)   = y_meas(k) − y0_del(k)     扰动 + 模型失配，一起吃掉
    y_pred(k)  = y0(k) + d_hat(k)          去掉死时间的预测值

PI 作用于 y_pred 而非 y_meas。死时间那 θ 分钟里，PI 不再"瞎等"，
它通过 y0 知道"水率的效果还在路上"，于是不再重复加码。

抗失配的由来：模型误差被 d_hat 吸收，反馈环节照常压回去。
实测 θ 差 3 倍（10 vs 30）、K 差 2 倍（−0.30 vs −0.151），
T3 合格率只波动 1~2 个百分点。

============================ 启用条件（重要）=============================

标定参数.py 里的 gain / tau / theta **目前是占位值**，取自
模型/replay_shift_model.py 的保守 FOPDT 核，不是实测值。

现场做受控阶跃试验拿到真实值后，只改 标定参数.py 那三个数，
其余代码不动，即可直接下控。

标定方法见 标定说明.md。
